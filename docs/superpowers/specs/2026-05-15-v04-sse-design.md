# v0.4 Server-Sent Events — Design Spec

**Date:** 2026-05-15  
**Status:** Approved

---

## Overview

Add Server-Sent Events (SSE) support to rxjs-stack. A route handler returns `stream$(source$, eventType)` instead of `json(data)`. The server keeps the connection open and pushes typed events as the source Observable emits. A client-side `fromEventSource<T>(url, eventType)` helper wraps the browser `EventSource` API as an Observable, closing the reactive loop end-to-end.

---

## Interface

### `SseEvent` (new, `src/server/core/types.ts`)

```typescript
export interface SseEvent {
  event?: string;
  data: unknown;
  id?: string;
}
```

### `stream$` helper (new, `src/server/core/response.ts`)

```typescript
export const stream$ = <T>(
  source$: Observable<T>,
  eventType?: string,
): HttpResponse
```

Returns an `HttpResponse` with `stream` set. Each source emission is wrapped as `{ event: eventType, data: emission }`. Callers pass raw data — not pre-wrapped `SseEvent` objects.

### `HttpResponse` change (`src/server/core/types.ts`)

```typescript
export interface HttpResponse {
  status?: number;
  body?: unknown;
  headers?: Record<string, string>;
  stream?: Observable<SseEvent>;   // new — presence signals SSE mode
}
```

When `stream` is present, `body` is ignored. `stream` is only ever set by `stream$()`.

### `fromEventSource` (new, `src/client/sse.ts`)

```typescript
export const fromEventSource = <T>(url: string, eventType: string): Observable<T>
```

Wraps `EventSource` as a cold Observable. Teardown calls `es.close()`.

## Data flow

### Server side

1. Route handler calls `stream$(source$, 'todos')` and returns the result
2. Router receives the `HttpResponse` with `stream` set
3. `respond` in `http.ts` detects `stream` and enters SSE mode:
   - Calls `res.writeHead(200, { 'Content-Type': 'text/event-stream', 'Cache-Control': 'no-cache', 'Connection': 'keep-alive', ...headers })`
   - Subscribes to `stream`
   - Each emission serialises as:
     ```
     event: <event>\n
     data: <JSON>\n
     \n
     ```
     (if `event` is undefined, the `event:` line is omitted)
   - `id` field written as `id: <value>\n` when present
   - On source complete: calls `res.end()`
   - On source error: calls `res.end()`
4. Client disconnect is detected via `req.raw.on('close', ...)` — triggers unsubscribe, which completes the source subscription

### Client side

```typescript
fromEventSource<Todo[]>('/api/todos/stream', 'todos')
  .subscribe(todos => render(todos));
```

Unsubscribing closes the `EventSource` connection.

## `TodoStore` change

`todos$: Observable<Todo[]>` added to the `TodoStore` interface and implementation — the existing internal `BehaviorSubject` exposed as a public Observable. No behaviour change: `setTodos` already calls `store$.next(...)`, so subscribers receive every mutation automatically.

```typescript
export interface TodoStore {
  getTodos: () => Todo[];
  setTodos: (todos: Todo[]) => void;
  reset: () => void;
  todos$: Observable<Todo[]>;   // new
}
```

## Demo endpoint

**Route contract** (`src/shared/routes.ts`):

```typescript
stream: defineRoute('GET', '/api/todos/stream')
```

Minimal entry — method + path only. SSE endpoints have no typed request body or response body, so `createClient` generation is not applicable.

**Effect** (`src/server/todos/todo.effect.ts`):

```typescript
stream$: req$ => req$.pipe(
  map(req => {
    const store = req.context.services.todoStore as TodoStore;
    return stream$(store.todos$, 'todos');
  }),
)
```

Wired in the server router alongside the existing todo routes.

## Testing approach

SSE streaming cannot be tested with `runRequest` (which resolves a single `HttpResponse`). Tests are scoped to units:

| Test | What it covers |
|---|---|
| `stream$()` returns correct headers stub and `stream` Observable | `response.test.ts` |
| `stream$()` source emissions wrapped as `SseEvent` with correct shape | `response.test.ts` |
| `respond` SSE branch — mock `ServerResponse` write/end spies assert chunk format | `http.test.ts` |
| `respond` SSE branch — client disconnect triggers unsubscribe | `http.test.ts` |
| `TodoStore.todos$` emits current value on subscribe | `todo.store.test.ts` |
| `TodoStore.todos$` emits on `setTodos` | `todo.store.test.ts` |
| `fromEventSource` emits parsed data on named events | `sse.test.ts` |
| `fromEventSource` unsubscribe closes `EventSource` | `sse.test.ts` |

No live HTTP integration test for SSE — requires real async timing, out of scope for v0.4.

---

## Acceptance criteria

- `npm test` passes
- `npm run typecheck` passes
- `stream$(source$, 'todos')` in a route handler emits correctly-formatted SSE chunks over a real connection
- Client disconnect unsubscribes the source Observable
- `fromEventSource<Todo[]>('/api/todos/stream', 'todos')` is usable as a drop-in replacement for polling
- `TodoStore.todos$` is a public Observable that emits on every `setTodos` call
